# Evaluate Sketch Sufficiency with an Origin-SyCCL Ablation

The core sketch-sufficiency evidence will exclude LLM-CCL candidate-generation results and will not rerun MILP solving. For each existing successful case, we take `algorithms[0]`, which Origin-SyCCL ranked first by its internal `final_schedule.time_us`, and use the root `src_graph` plus `final_schedule` recorded together in that entry. FlowSim-rs deterministically expands the root sketch, while the archived `final_schedule` is the MILP arm. Both schedules are then evaluated by the same `synthesize resim` build and configuration, with resim `Time` as the primary measurement and solve-time `alg_times` retained only as a consistency check. Combined-sketch membership and chunk-allocation ratios are deliberately outside this ablation; an audit of 40 available H800 multirail best-result artifacts found one component with ratio 1.0 in every case. This solver-favored paired ablation isolates the value of lower-level MILP scheduling for the selected root sketch; the resulting claim concerns conditional sketch sufficiency within the tested domain, not universal solver irrelevance or end-to-end LLM-CCL performance.

The primary paired ratio is `R = BW_det / BW_MILP = Time_MILP / Time_det`. We classify `R < 0.95` as deterministic expansion being weaker, `0.95 <= R <= 1.05` as practical equivalence, and `R > 1.05` as deterministic expansion being stronger. Absolute algorithm bandwidth is computed as the total message size encoded in the case name divided by common-resim completion time, in decimal GB/s. The H800 experiment scripts divide that total size by GPU count when producing `coll.byte` for both AllGather and Alltoall, so `coll.byte` is not used as the bandwidth numerator.

Deterministic schedule construction will use FlowSim-rs's root-sketch translator and its SyCCL-compatible translated-schedule export, not the modified SyCCL direct-sketch resim path. FlowSim-rs is only the expander: its own simulated `time_us` is discarded. The exported schedule and the MILP-generated schedule are both evaluated by the designated H800 SyCCL resimulator.

The debug build is accepted because expander runtime is not a performance endpoint; only its exported schedule is evaluated, and all official timing comes from the common H800 SyCCL resimulator.

The experiment domain is restricted to successful, parseable H800 multirail results already present under `/home/antl/wzd/origin-syccl/h800_build/syn_res`: 32-host AllGather and Alltoall plus 64-host AllGather. Missing or unfinished result files are excluded, and results from `/home/antl/wzd/origin-syccl/build/syn_res` are not mixed into this experiment.

For each result file, the paired artifacts are taken only from `algorithms[0]`: `sketch.sketches[0].src_graph` supplies the deterministic arm, and `final_schedule` supplies the archived MILP arm. The MILP entry is mechanically isolated into a one-algorithm resim input so the common evaluator cannot re-rank or select another schedule.

Semantically duplicate result files, such as integer-named and `.0B`-named runs whose configurations differ only in numeric encoding and output path, are not counted as separate workloads. The primary analysis contains 27 unique workloads and prefers the integer-named artifact. Duplicate historical solves are retained only for a separate sensitivity analysis of solver-run variability.

The domain-wide non-inferiority claim has a strict worst-case gate: all 27 unique primary workloads must satisfy `R >= 0.95`. A geometric mean, median, or majority of passing cases cannot hide a failing workload. If any case falls below the margin, the paper must report the exact passing count and failure scope instead of claiming non-inferiority throughout the tested domain.

Superiority is reported at two levels. A workload counts as a scenario where deterministic expansion is stronger only when `R > 1.05`, and the paper must state the exact count `N/27`. Domain-wide superiority may be claimed only if all workloads pass non-inferiority and the geometric mean paired ratio exceeds `1.05`; otherwise the wording is limited to overall equivalence with higher performance in the enumerated scenarios.

If an archived MILP arm re-simulates successfully but FlowSim-rs translation or deterministic-schedule resimulation fails, the workload remains in the primary set with an explicit `translate_failed` or `resim_failed` status. No numeric ratio is fabricated, and the failure automatically prevents a domain-wide non-inferiority claim.
