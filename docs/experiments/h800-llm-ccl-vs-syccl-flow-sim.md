# H800 llm-ccl vs SyCCL Flow-Sim Experiment Plan

## Goal

Compare llm-ccl and origin SyCCL on H800 multirail cases by evaluating the final algorithms in the same `flow-sim-rs` simulator.

The primary metric is simulator time from `flow-sim-rs`, not SyCCL's internal `alg_times`.

Cases:

1. 256 GPU H800 Allgather.
2. 256 GPU H800 Alltoall.
3. 4096 GPU H800 Allgather, where origin SyCCL is expected to fail or time out.

All cases use the H800 topology generated by SyCCL's default `config_gen.py` semantics.

## Non-Goals

- Do not use the SyCCL two-agent path in llm-ccl.
- Do not compare real hardware runtime.
- Do not calculate dollar cost in this experiment. Record token usage only.
- Do not hand-write an alternative H800 topology for llm-ccl.

## Fixed Components

### SyCCL

Origin SyCCL must run from a clean independent worktree at:

```text
commit: 855a184ed0746b46595763661345d76812c9a7dd
recommended worktree: /root/origin-syccl-h800-855a184
```

Do not use the current dirty `/root/origin-syccl` checkout for generation, solving, or config provenance.

Apply only one local patch to the clean worktree: update `solve()` in these files so stdout and stderr are both written to the log while still printing to the terminal:

- `scripts/runexp.py`
- `scripts/runexp_scale.py`
- `scripts/runexp_reverse.py`

The patch should replace the current shell string plus `tee` implementation with a non-shell `subprocess.Popen(..., stderr=subprocess.STDOUT)` loop. Non-zero solve exits must raise `subprocess.CalledProcessError`.

Record in provenance:

- base commit;
- logging patch diff;
- run script hashes;
- built `synthesize` binary hash.

### flow-sim-rs

Within one experiment launch, all cases must use one fixed `flow-sim-rs` binary.

Recommended launch bundle layout:

```text
experiments/h800-flow-sim-compare/<timestamp>/
  bin/flow-sim-rs
  provenance/flow-sim-rs.sha256
  provenance/flow-sim-rs.git.txt
```

Different experiment launches may upgrade `flow-sim-rs`, but one launch must not change the binary mid-run.

Record:

- absolute path;
- sha256;
- git commit;
- dirty diff summary, if any.

## Canonical Configs

The SyCCL config JSON is the single source of truth for topology, collective, message-size semantics, and layer/group constraints.

Every canonical config must be generated from the fixed SyCCL worktree. llm-ccl must consume those configs; it must not independently derive or override H800 topology fields.

Message-size semantics:

- `total_message_size` is the file-name prefix generated by SyCCL scripts, for example `16777216B-prune=small`.
- `coll.byte` is the value inside the config and equals `total_message_size / GPU_NUM`.
- `flow-sim-rs` evaluates using `coll.byte`.
- Reports must include both values.

Case generation:

```text
256 GPU Allgather:
  ConfigGen.h800conf(chunk_size_B, nhosts=32, ngpus=8, nnics=8, nrails=8, a2a=False)

256 GPU Alltoall:
  ConfigGen.h800conf(chunk_size_B, nhosts=32, ngpus=8, nnics=8, nrails=8, a2a=True)

4096 GPU Allgather:
  runexp_scale.py h800-scale, using the nhosts=512 group only
  ConfigGen.h800conf(chunk_size_B, nhosts=512, ngpus=8, nnics=8, nrails=8, a2a=False)
```

Run the full default SyCCL sweep for each case group, not a single message size.

## llm-ccl Path

Use SimpleTES with `llm_elite`. Do not use:

- `agent/syccl_agents/runner.py`;
- `agent/simpletes/engine/syccl_two_agent.py`;
- the SyCCL two-agent workflow.

The llm-ccl candidate interface remains the current compact single-root sketch:

```python
(step, layer, group, srcs, dsts)
```

The LLM generates one GPU-0 broadcast tree. `flow-sim-rs` expands it according to the config collective:

- Allgather: rotate the tree across all roots.
- Alltoall: trace paths from the same tree for each `src -> dst` pair.

Required SimpleTES settings per case:

```text
selector: llm_elite
strategies: linear_rank, balance, all
k_candidates: 4
max_generations: 10000
num_chains: 1
k_candidates is counted inside max_generations as candidate attempts
save_llm_io: enabled
```

The run script must pass:

```bash
--save-llm-io
--selector llm_elite
--elite-selection-strategy <linear_rank|balance|all>
--k-candidates 4
--max-generations 10000
--num-chains 1
```

Use the canonical config for the case:

```bash
export SYCCL_BASE_CONFIG=/path/to/canonical-config.json
export FLOW_SIM_BIN=/path/to/launch/bin/flow-sim-rs
export SYCCL_EVAL_ARTIFACT_DIR=/path/to/case/eval_artifacts
```

### llm-ccl Result Selection

Use the evaluator outputs produced during the run as the main result. Do not re-run all llm-ccl candidates as the default result selection method.

Instead, enforce provenance:

- `candidate-config.json` hash must match the canonical config hash for the case.
- evaluator flow-sim output must be from the fixed launch binary.
- `flow-sim-manifest.json` and referenced output JSON must exist.
- output timestamps must be inside the run window.
- the run must record the expected `flow-sim-rs` binary hash.

If provenance fails, mark the case or strategy `invalid_provenance` and rerun it.

Primary llm-ccl result:

```text
llm_best_flow_sim_us = min(valid evaluator outputs across linear_rank, balance, all)
```

Also report each strategy separately.

### Token Usage

Token usage must be recorded, but cost calculation is out of scope.

Because the SimpleTES CLI only saves token usage when LLM I/O is enabled, `--save-llm-io` is mandatory.

Aggregate token fields from checkpoint nodes:

- `prompt_tokens`
- `completion_tokens`
- `total_tokens`
- `reasoning_tokens`

Report by:

- case;
- strategy;
- total run;
- best-producing strategy.

Do not report `api_cost_usd` as a result in this experiment.

## origin SyCCL Path

Run origin solve from the fixed SyCCL worktree.

Use an outer timeout of `10h` for every solve. Keep the internal config generated by SyCCL unchanged, including `mip_config.time_limit_h=5`.

Failure classification:

```text
origin_status=ok
  result JSON exists, is parseable, and contains at least one algorithm.

origin_status=timeout
  outer 10h timeout fires.

origin_status=oom
  process/log indicates OOM, killed, or memory exhaustion.

origin_status=solve_failed
  process exits non-zero, result JSON missing, or result lacks algorithms/alg_times.
```

For 4096 GPU Allgather, keep the generated config and failure log even if solve fails. Continue llm-ccl evaluation for the same canonical config.

### origin Result Selection

If origin solve succeeds, do not use `alg_times` directly as SyCCL performance.

Run all solved algorithms through `flow-sim-rs`:

```bash
flow-sim-rs simulate \
  --config origin-config.json \
  --translated origin-result.json \
  --output origin-all-flow-sim.json
```

Select SyCCL performance by the best `flow-sim-rs` solution:

```text
syccl_flow_sim_us = min(solutions[*].rust_time_us)
syccl_flow_sim_solution_index = argmin(solutions[*].rust_time_us)
```

Also report SyCCL's original best internal time as a reference column:

```text
syccl_alg_times_best_us = min(result.alg_times)
syccl_alg_times_best_index = argmin(result.alg_times)
```

These two indexes may differ. The main comparison uses `syccl_flow_sim_us`.

## Required Scripts

### 1. SyCCL Worktree Setup

Create the clean fixed worktree, apply logging patch, build `synthesize`, and write provenance.

Expected output:

```text
<bundle>/provenance/syccl-worktree.json
<bundle>/origin-syccl-h800-855a184/
```

### 2. Config Generator

Generate canonical configs for:

- 256 GPU Allgather;
- 256 GPU Alltoall;
- 4096 GPU Allgather via `runexp_scale.py` 512-host semantics.

Expected output:

```text
<bundle>/configs/<case_id>/config.json
<bundle>/configs/manifest.json
```

### 3. llm-ccl Launch Generator

Generate SimpleTES run scripts for every `(case, strategy)` with:

- `--save-llm-io`;
- `--selector llm_elite`;
- `--elite-selection-strategy`;
- `--k-candidates 4`;
- fixed `FLOW_SIM_BIN`;
- fixed `SYCCL_BASE_CONFIG`.

### 4. origin Solve Runner

Run each origin config under 10h timeout and record:

- status;
- wall time;
- stdout/stderr log;
- result JSON if produced.

### 5. origin Flow-Sim Runner

For every successful origin result, run all algorithms through `flow-sim-rs simulate` and select best `rust_time_us`.

### 6. llm-ccl Summarizer

Read evaluator artifacts and checkpoints, validate provenance, and aggregate:

- best `time_us` per strategy;
- overall llm best;
- candidate counts;
- token usage.

### 7. Final Report Builder

Join config manifest, llm-ccl summary, origin solve summary, origin flow-sim summary, and provenance into CSV/JSON.

## Acceptance Checks

Before trusting results:

- Every case row has a canonical config hash.
- Every llm-ccl evaluator `candidate-config.json` matches the canonical config hash.
- Every llm-ccl row was produced with `--save-llm-io`.
- Every row uses the same `flow-sim-rs` binary hash inside one launch.
- origin SyCCL worktree is exactly `855a184ed0746b46595763661345d76812c9a7dd` plus the logging patch.
- origin logs contain both stdout and stderr.
- origin successful results are selected by `flow-sim-rs rust_time_us`, not `alg_times`.
- 4096 GPU origin failure is classified and preserved rather than silently dropped.
